# Постоянный ключ подписи Spoty

Все сборки приложения (локальные и из GitHub Actions) подписываются **одним и тем же ключом** —
поэтому каждая новая версия устанавливается поверх предыдущей, без удаления приложения и потери данных.

| Файл | Назначение |
|------|-----------|
| `spoty-release.p12` | хранилище ключей (PKCS12), алиас `spoty`, RSA-4096, действует до 2056 г. |
| `signing.properties` | пароли и имя алиаса для сборки |
| `CERT_SHA256` | отпечаток сертификата. CI сверяет его с подписью готового APK и **падает**, если ключ случайно изменился |

## ⚠️ О безопасности

Репозиторий публичный, а у меня (создавшего ключ) нет права записывать GitHub Secrets, поэтому ключ лежит в репозитории,
чтобы автосборка работала сразу и без ручной настройки. Это значит, что любой, кто видит репозиторий, технически
может подписать свой APK этим ключом. Для личного использования риск минимален (установить такой APK должны вы сами),
но если приложение станет публичным — переведите подпись на секреты:

1. Создайте новый ключ: `scripts/generate-keystore.sh`.
2. В **Settings → Secrets and variables → Actions** добавьте секреты  
   `ANDROID_KEYSTORE_BASE64` (`base64 -w0 новый.p12`), `ANDROID_KEYSTORE_PASSWORD`,  
   опционально `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEYSTORE_TYPE`.
3. Workflow автоматически начнёт подписывать этим ключом (проверка отпечатка при этом отключается).
4. Удалите `signing/spoty-release.p12` и `signing/signing.properties` из репозитория (и из истории).

> Смена ключа меняет подпись приложения: установленную версию придётся удалить и поставить заново
> (перед этим сделайте экспорт медиатеки: Настройки → Резервная копия).

## Проверка подписи вручную

```bash
apksigner verify --print-certs Spoty-*.apk
# Signer #1 certificate SHA-256 digest: e8def5b2019ce0525b93df0871b90a878e134165afbc36f5fb6c527a782e7ff2
```
